# 采集策略

执行规范以README.md、config/collection.json与collection_policy.py为准。

## 范围与容量

固定5款游戏，窗口为北京时间2026-08-23至2026-11-21（结束不包含），简体中文、全部推荐状态和购买来源、不预先过滤题外活动。按月份倒序，每页100条。

每款游戏全部月份的正式评测JSONL默认100 MB（十进制），跨任务累计；允许显式覆盖。没有最低条数、默认总条数限制、旧版1 GiB整目录预算或3小时限制。默认另保留5 GB磁盘余量。

## 停止与恢复

正常空页才标记月份完成。容量不足整页拒绝，文件/数据库/游标均不提交；只停止该游戏。STOP、低磁盘与可选运行时间暂停任务。显示实际覆盖日期与停止原因。

恢复时校验游戏、窗口与请求条件，读取冻结策略，重放pending_page，再从正式文件重算容量。显式容量调整记入manifest.policy_changes，不能清零已用额度。

## 保存与分析

数据按游戏和评测发表月份组织，review_locations关联每个ID的原分片，重跑更新而不重复。任务仅有参数、进度、错误和摘要。

容量截断是近期优先数据，不是随机样本；统计和未来Agent必须说明覆盖范围与完整性。当前游玩状态与发表时状态分别使用。

## 维护

2026-11-22已迁移目录。旧执行报告中的数量不是现有数据量证据，以当前文件与数据库为准。迁移逐条核对后删除旧目录，不留备份。
